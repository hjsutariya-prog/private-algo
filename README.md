# Private Algo Desk — local strategy workspace

A local Python application for strategy drafts, historical backtests, read-only Zerodha prices and a persistent real-quote paper execution lab. **It cannot place broker orders.** The paper lab is an acceptance test, not an autonomous strategy deployment. See [PENDING_TASKS.md](PENDING_TASKS.md) for actual completion status and [PAPER_SERVICES.md](PAPER_SERVICES.md) for operation and limits.

## What works now

### Trading-desk interface (30 September 2026)

The default Trading desk is a **Live unavailable** view, not a live deployment. Navigation is Trading desk, Strategies, Positions & orders, Research, Activity and Connections. Mode, broker connection, price freshness and the disabled strategy-entry status stay visible. The Paper view reads only the separate local paper ledger. Switching views never changes execution permissions or deploys a draft.

Open paper positions are grouped by test, expiry and call/put direction. Protection requires matching executed long quantities, correct strikes and expiry, and consistent fill records. Pending hedge buys, unknown outcomes and incomplete metadata cannot claim confirmed protection. Orders and recent execution/recovery history are inspectable; older outstanding orders are retained outside the recent-history limit. Empty paper records are distinct from unavailable broker records. Paper marks use the existing recorded-first/estimated-fallback calculation, explicitly separate from executions. Cumulative paper totals are not labelled today's profit.

Broker account identity, positions, reconciliation, margin, daily realised P&L, enforced daily loss limits and autonomous strategy deployment remain unavailable. The four trading controls are individually disabled with their scope explained. The old paper recovery-close button is also disabled: its current loop does not guarantee shorts-first closure and must not be presented as protection-safe. The engine and its strategy rules were not changed. The existing manual paper order lab remains separate; its pause stops all paper order processing, not only new entries.

The Tradetron bridge has a protected, paper-only signal outbox. It can retain validated BANKNIFTY entry, exit and hedge-replacement events and uses separate counters for each call/put action. A Tradetron API response is recorded as **accepted, not confirmed**: it is not treated as a Tradetron paper fill or a broker fill. A failed or interrupted request is marked uncertain and is never retried automatically. The bridge is disarmed by default and there is intentionally no dashboard control that can turn it into an automatic sender yet.

For isolated browser examples, run `python -B -m tests.preview_trading_desk` and open port 8766. It uses temporary databases, invented data, a visible fixture warning and rejects all writes. It must never be used as trading evidence. Additional interface checks: `node --test tests/trading_desk.test.cjs tests/workspace_ui.test.cjs tests/paper_ui.test.cjs tests/report_ui.test.cjs`.

Option pricing now prefers recorded prices and uses labelled estimates only where eligible data is missing. During a signed-in replay, the app loads the current BANKNIFTY option catalogue, checks every eligible 500-point ATM/ITM short strike at each entry minute, selects the recorded premium closest to ₹1,000, and then saves candles for that selected contract and the exact hedge contracts. It also reads the old engine's saved option cache without modifying it and archives future observed option quotes. Expired contracts absent from Kite's current catalogue cannot be fetched by guessing a token; existing saved candles can still be used, otherwise the result remains an estimate. Estimates never create paper fills. See [BACKTEST_MODEL.md](BACKTEST_MODEL.md) for exact matching and fallback rules and [PAPER_SERVICES.md](PAPER_SERVICES.md) for live-paper valuation limits.

Latest rule change: new backtests fix each directional trade's stop and target to the completed signal-hour close (10:15, 11:15, and so on), in both entry-timing modes. Later execution does not shift these levels. An entry already at or beyond either level is skipped. Existing positions keep their original levels through later hours and rollover; hedge replacement rules are unchanged. Actual entry prices still determine profit. Old backtests require a rerun and are labelled legacy, not silently converted.

- Create multiple named drafts with fixed lots and planning capital; edit those fields separately.

- Use the current BANKNIFTY rules as a shared starter template. Rule editing and other strategy types are not implemented yet.
- Exercise pure rule functions for strict 1,000-point crossings, hedge strikes/targets, fixed short stops/targets, and a Monday rollover cutoff from supplied expiry/session dates.

- Keep the original directional spot reference when deciding between a terminal exit and a roll.
- After a user-configured Kite sign-in, download the current NFO instrument catalogue and request a timestamped BANK NIFTY spot quote. This is a manual snapshot, not a streaming feed.
- Replay up to five calendar years of Zerodha BANK NIFTY spot prices through the latest completed session. Downloads use non-overlapping 59-day batches, paced below Kite's historical request limit. Progress is shown, a running replay can be stopped, and refreshing the page restores its current work or result while the local process remains open. Entry candles require exactly 60 unique consecutive minutes, anchored at each configured session opening, using the named boundary or review timing setting. This includes verified weekend, split and Muhurat sessions; short or incomplete hours are ignored independently, never joined across a scheduled break. Per the user's rule, whole-empty expected trading days after successful downloads are assumed holidays; partial days and failed requests are not.
- Show hypothetical directional entry and exit spot levels, fixed 500-point stops and 1,000-point targets, and favourable movement in index points. Default comparison entry uses the completed-hour boundary opening price; a separately named 20-second review mode uses the next full minute. A signal at session close, or with a missing scheduled entry price, is skipped. Positions start empty, carry overnight, and require a fresh signal after an exit. Per the latest user rule, missing minutes are skipped and monitoring resumes at the next available price. Full 60-minute entry candles remain mandatory. No prices are filled in; reports list skipped minutes and label results approximate because triggers inside gaps may be missed. An isolated missing minute still gets one narrow broker re-fetch before it is skipped.
- Apply the shared option-premium model to the current spot strategy: recorded-price selection first for every eligible 500-point ATM/ITM selling strike nearest ₹1,000 premium, then a clearly labelled ₹1,000 model fallback when no exact eligible candle exists. Known CE/PE hedge strikes likewise use their exact recorded candles first. Marginal movement bands, calendar-time decay, independent hedges, next-minute replacements and Monday 15:15 monthly rollovers remain unchanged. Configure lots and comparison units independently of saved draft planning fields; show selling/hedge ledgers, dated charges, closed profit and open estimates separately. See [BACKTEST_MODEL.md](BACKTEST_MODEL.md) for the adapter contract, full assumptions, sources and limits.

The order-safety checks use artificial data. The past-data replay uses real spot prices after Zerodha sign-in and requests exact option candles only when their contract remains identifiable in Kite's current catalogue or is already saved locally. Spot points remain separate from option P&L. Recorded candles are price proxies, not historical fills, and missing observations retain explicitly modelled premiums. Within-minute stop/target order is unknown. Default comparison mode marks collisions uncertain without an exact exit or P&L; the separately named review mode uses an explicitly approximate stop-first assumption. Neither check proves profitability. The offline order-rehearsal lot size is deliberately 10 fixture units; the option comparison defaults to 30 assumed units per lot. Neither is a claim about contract size on every historical date. The connector's automated tests use invented broker responses; a separate manual sign-in and after-hours snapshot request succeeded on 29 September 2026. That is not a market-hours or strategy test.

## Start on this computer

Run Python 3.11 or newer from this folder:

```powershell
python app.py
```

Then open http://127.0.0.1:8765. Stop the local process with Ctrl+C. Existing historical/offline features use the standard library. For streaming, install the pinned dependency once with `python -m pip --isolated --disable-pip-version-check install --target .deps -r requirements-stream.txt`. If the port is busy, stop the old app or use `python app.py --port 8766`; two servers cannot share one address.

The app binds only to 127.0.0.1 and contains no live mode or broker-order endpoint. It has local API key and secret fields for Kite market-data access. By default, details stay in process memory. The optional **Remember on this Windows account** setting saves only the app key and secret in `data/private-algo-kite.dpapi`, encrypted with Windows user-scoped DPAPI (never machine-wide or plain text). With a custom `--data` location, the protected file uses that database's folder and filename stem. Login tokens stay in memory: a restart or token expiry still requires manual Zerodha sign-in. Forget connection details removes the protected file and clears memory, but does not revoke the token at Zerodha. Unchecking Remember when submitting new details removes any previous saved copy. A failed save/delete is reported, not treated as success. An unreadable protected file is not silently discarded; setup shows a recovery message. There is no plaintext fallback on unsupported systems.

This is a development server, **not an internet-facing production service**. Do not expose it publicly. Windows account protection does not protect against programs running as that user, and may not survive a move to another account/computer or an administrator password reset. Same-computer users/processes can access the app; this prototype is not multi-user authenticated software. A normal Kite token may allow more than market data at Zerodha, even though this app has no order routes. See [Windows protection documentation](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) and [Kite session expiry](https://kite.trade/docs/connect/v3/user/).

Drafts and artificial checks are in `data/private-algo.sqlite3`. Paper orders, quote evidence, events and acceptance results are in `data/private-algo-paper.sqlite3`; they do not change backtest results or deploy drafts. Do not place passwords, API keys or broker credentials in strategy names or files. This project did not create hosting, subscriptions, a developer account, or API keys.

## Connect market data manually

1. In your Kite Connect developer app, set the Redirect URL to `http://127.0.0.1:8765/api/kite/callback` (change the port if you started the desk on another port).
2. In the local dashboard's Connections panel, enter your Kite API key and API secret. Optionally select **Remember on this Windows account** so future app starts load them automatically. Do not put your Zerodha password, one-time code, or app secret in chat.
3. Select **Sign in at Zerodha** and complete login on Zerodha's own page. Return to the dashboard, then request a BANK NIFTY spot quote, download the daily instrument list, or choose a start date and select **Replay from this date**.

The connector does not place orders or run the strategy. It does not refresh the login silently. The quote shows the broker timestamp and warns when older than two minutes or ahead of this computer's clock. The instrument file's prices are not live; the dashboard shows contract counts, lot sizes and listed expiries, not trading signals. For technical data limits, see [KITE_READ_ONLY.md](KITE_READ_ONLY.md).

## Visual design

The visual redesign takes inspiration from the charcoal-and-blue layout of [Algorithmic Trading Dashboard on Awwwards](https://www.awwwards.com/sites/algorithmic-trading-dashboard). It uses original local markup and icons, without copied branding or external fonts/scripts. Summary counts come from saved drafts and the latest 20 offline checks; the separate historical replay labels hypothetical spot-point results explicitly.

### Backtest report

The full-width report separates Overview, Positions, Signals, Data quality, Option model and Hedge ledgers. New results open the Option model tab, with closed net, open estimate, total charges, combined net and a three-ledger breakdown. Selling and hedge records include expandable calculation details; separate disclosures show model settings, per-order charges and rollover history. The original spot chart and strategy details stay separate. Tables support filters, search, newest/oldest ordering and 20-row pages. Keyboard arrow keys switch report tabs; narrow screens keep wide tables inside their own horizontal scroll area.

Missing-minute histories now continue with an explicit approximate-result warning, gap count and dated details. Pending hedge replacements and rollovers use the next available minute open and disclose any delay; existing spot stops and targets do not move. Invalid prices, duplicates, unknown hours and missing calendar/fee configuration still stop calculations. Spot and option calculations have separate completion states, and partial figures remain limited to the accepted portion. Signals after a hard cutoff do not imply trades. Old in-memory reports are not rewritten and require a rerun. A process restart clears the market-data login and in-memory report, not saved strategies.

The earlier report redesign was checked against the saved real 1 January 2024–29 September 2026 result: 683 signals, with position tracking stopping at the previously unsupported 20 January Saturday session. That session is now configured, but the old result is not rewritten: it must be rerun with real data. Browser checks covered signal paging, filters, empty search, hedge disclosures and desktop/narrow-screen layouts. The new isolated special-session fixture verifies a 45-minute period ignored for entries, one full hour, the closing signal marked Skipped, and an existing position stopped during the short period. These checks verify software behavior and presentation, not strategy profitability.
